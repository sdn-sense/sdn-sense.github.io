## What changed

- The topology page now uses Archify instead of the NeXt UI graph. It can filter to an active connection, show the path and VLAN at each hop, expose device health, and represent link speed and port-channel membership.
- `POST /{sitename}/deltas` accepts an `Idempotency-Key`. Repeating a request with the same user, key, and payload replays the stored result instead of creating a duplicate operation.
- Delta and model list endpoints now support offsets and report the matching total through `X-Total-Count`. The Web UI uses the same paging model.

## Reliability fixes

- The `forceapply` action no longer fails on a dependency-key error, and ProvisioningService can process the queued request correctly.
- Frontend startup now rejects missing, template, or shell-unsafe MariaDB passwords with a clear reason. MariaDB initialization failures remain visible to readiness checks.
- Agent image builds no longer depend on an expired EPEL RPM URL, and the Frontend build works around the `python-dateutil` package conflict.

## Before upgrading

- Validate `MARIA_DB_PASSWORD` before starting the Frontend. The Frontend rejects unset values, `REPLACEME`, whitespace, and shell-sensitive characters documented in the [Frontend configuration]({{ '/customization/configuration-frontend/' | relative_url }}).
- The startup repositories now use `--restart unless-stopped`. A container stopped by an operator remains stopped across Docker or host restarts.
- The Frontend image includes Node.js 22 and the pinned Archify renderer. Sites that build images locally must update `siterm-startup` first.
- Topology health, WAN, and port-channel details appear after SNMPMonitoring regenerates `topology.json`.

SiteRM 1.6.5 supports Frontend EL9, Agent EL9/EL10/Ubuntu 22, and Debugger EL10 images. EL10 remains the default Agent image.
