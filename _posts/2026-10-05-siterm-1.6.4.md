## What changed

- A new BGPMonitoring service records normalized peer summaries for switches that carry active SENSE BGP deltas. Operators can inspect the data or request a rescan through the REST API and Web UI.
- The Validator reports stable error codes when BGP data is missing, a SENSE peer is not established, or an established peer receives or advertises no prefixes.
- SNMPMonitoring exports BGP session state, received and advertised prefixes, session uptime, and last-scan timestamps to Prometheus.

The supporting Ansible templates and vendor collections add BGP summary collection for FRR, SONiC, Junos, Cisco NX-OS, Dell OS9, and Dell OS10.

## Reliability fixes

- Frontend base-image builds use the current MariaDB signing key.
- Startup scripts no longer forward an empty network-mode argument.
- A stale Ansible index lock or broken checkout is recovered automatically, and configuration preparation failures stop startup instead of leaving a partially configured Frontend running.
- `ansible-prepare.py` now rejects missing network OS values, missing credentials, invalid SSH key paths, and malformed YAML with specific errors.

No manual database or configuration migration is required. BGP monitoring activates when a switch already has `private_asn` configured and carries an active BGP delta.
