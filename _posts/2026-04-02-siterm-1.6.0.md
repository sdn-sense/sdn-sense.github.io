## Authentication replacement

SiteRM 1.6.0 replaces the previous certificate-only REST authentication layer.

- Human users authenticate with username and password and receive a short-lived bearer token plus a rotating refresh token.
- Agents, Debuggers, and automated services sign a server challenge with their X.509 private key before receiving tokens.
- `/.well-known/jwks.json` and `/.well-known/openid-configuration` support standards-based verification by other tools.
- The Frontend includes `siterm-usertool` for local account administration and generates an RSA signing key at startup.
- New `users` and `refresh_tokens` tables are created through the release migration.

The release also restricts HTTP methods, rate-limits authentication endpoints, hardens token validation, updates the Web UI to bearer authentication, and adds optional OpenTelemetry tracing.

## Required upgrade review

This is a breaking upgrade from 1.5.63. Coordinate service cleanup with the SENSE team and follow the deployment-specific migration procedure before starting the new image.

- Certificate mounts move to `/etc/secret-mount/tls.crt` and `/etc/secret-mount/tls.key`.
- Review the allowed trust-store issuers if the site uses a non-standard CA.
- Agent and Debugger deployments no longer require their own host certificate under the new machine-to-machine flow.
- EL8 images are no longer supported.

Read the [authentication guide]({{ '/customization/authentication/' | relative_url }}) before upgrading.
